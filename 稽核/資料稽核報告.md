## 4. 交叉稽核發現

### 4.1 馬達的兩個訊號：溫度是「預警」，震動是「故障」

報告結論為「馬達盯溫度 > 80°C、壓力計盯震動 ≥ 15」。交叉檢查馬達的狀態分布：

| 馬達 | error | warning | normal | offline |
|---|---:|---:|---:|---:|
| 溫度 ≤ 80°C | 322 | 0 | 19,370 | 400 |
| 溫度 80～100°C | 8 | **154** | 185 | 6 |
| 溫度 > 100°C | **55** | 0 | 0 | 0 |
| 震動 ≥ 15（338 筆） | **332** | 0 | 0 | 6 |

- 馬達 **warning 154 筆全部**出現在溫度 > 80°C，溫度 > 100°C 則全部為 error。
- 馬達 error 385 筆中，**332 筆（86%）發生在震動 ≥ 15**，溫度 > 80°C 的只有 63 筆（16%）。

**判定：結論沒有矛盾，但需補充。** 溫度 > 80°C 是馬達的「預警」訊號；震動 ≥ 15 則是「故障」訊號，而且同時適用於馬達與壓力計。這也解釋了「馬達 error 最高（1.88%）、warning 最低（0.75%）」：馬達的 error 多數來自高震動，而高震動之前沒有出現 warning。

**報告用語已調整為：** 馬達要盯溫度（> 80°C 開始出現預警），馬達與壓力計都要盯震動（≥ 15 幾乎都是故障）。

### 4.2 數字說法微調

| 馬達時段耗電差距 | 約 7% | 以最低值為分母為 7.6%，以最高值為分母為 7.1% | 口頭報告改為「約 7%～8%」，被問時說明分母 |

## 5. 資料特性觀察

稽核過程中觀察到下列特性，已納入報告的「限制」說明：

| 觀察 | 內容 |
|---|---|
| 數值分布均勻 | 馬達溫度 30～80°C 每 5°C 約 2,000 筆；壓力、耗電亦接近均勻分布 |
| 無時段差異 | 馬達每小時平均耗電僅差約 7%～8% |
| 筆數完全一致 | 45 台設備皆為 2,050 筆 |
| 狀態與門檻高度對應 | 溫度感測器溫度 > 48°C、壓力計溫度 > 55°C 或震動 ≥ 15、馬達溫度 > 100°C 或震動 ≥ 15 時皆為 error |
| offline 隨機出現 | 約 2%，與各項感測值無明顯關聯 |
| 時間欄位 | `created_at` 為資料匯入時間（2026-11-01～02），分析一律使用 `timestamp` |

上述特性顯示資料可能為模擬資料，因此報告結論著重於**相對比較**與**門檻前後的差異**；`status` 的判定規則列為待資料提供方確認的事項。

## 6. 重現方式

```bash
pip install pandas
cd 稽核
python iot_data_audit.py
```

程式預設讀取 `tim/作業.twbx` 中打包的原始 CSV，不需連線資料庫；也可指定其他 CSV 或 .twbx 檔案路徑。執行後逐項印出 `[PASS]` 或 `[FAIL]` 與實際數值，最後顯示通過數。

## 7. 數字出現微小差異時的常見原因

| 原因 | 說明 |
|---|---|
| 四捨五入位數 | 98.46% 與 98.5%、1.99% 與 2% 為同一數值的不同表示 |
| 分母不同 | 比例需確認分母是「全部資料」還是「某類設備」；Tableau「合計百分比」需確認計算方向 |
| NULL 處理 | Tableau 的 SUM／AVG 與 SQL 的 `COUNT(欄位)` 會排除 NULL，`COUNT(*)` 則不排除 |
| 邊界值 | `> 80` 與 `>= 80` 相差 1 筆（有 1 筆恰為 80.00°C）；震動門檻需與計算欄位寫法一致 |
| 時間解析與時區 | timestamp 若被讀成文字或時區設定不同，「小時」分組會偏移 |
| 擷取設定 | 擷取若設定篩選或隱藏欄位，筆數可能少於原始資料（本專案擷取為完整 92,250 筆） |
| 浮點數加總 | 大量小數相加末位可能有誤差，比對時允許 ±1 |
