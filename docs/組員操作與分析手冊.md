> 給：不熟 Tableau 與資料分析的組員。2026-11-10 由 5 號 BI 專家編寫（第 2 版：直接告訴你欄位拖去哪）。
> 用法：照「操作步驟」一步一步做；做完對照「你應該看到」；再讀「怎麼解讀」與「怎麼講」。

## 0. 先看懂這份資料

**這是什麼：** 工廠設備的「體檢紀錄」。設備上裝了感測器，每隔一段時間回報一次溫度、壓力、震動、耗電，以及狀態。
**報告對象：** 工廠設備維運主管。他最在意：**哪些設備可能出問題、電花在哪裡**。

| 項目 | 內容 |
|---|---|
| 資料表 | `iot_sensor_logs`（92,250 筆、11 欄） |
| 設備 | 45 台，每台 2,050 筆：馬達 motor 10 台、壓力計 pressure_gauge 15 台、溫度感測器 temperature_sensor 20 台 |
| 時間 | 2025-01-01 00:00 ～ 2025-01-29 11:57（**1/29 不是完整一天**） |
| 狀態 status | normal 94.7%、offline 2.0%、warning 1.9%、error 1.4% |
| 欄位 | `log_id、timestamp、device_id、device_type、temperature、pressure、vibration_level、power_consumption、status、factory_zone、created_at` |

### 名詞白話

| 名詞 | 白話 |
|---|---|
| 馬達（motor） | 讓機器動起來的動力來源，最耗電 |
| 壓力計 | 量管線或容器壓力；只有它有壓力值 |
| 溫度感測器 | 量溫度；沒有震動值 |
| warning | 還沒壞，但有徵兆 |
| error | 出問題了 |
| offline | 設備沒有回報 |
| 描述性分析 | 只描述「發生了什麼」，不證明「為什麼」 |

### 空白不是錯誤

`pressure` 有 61,500 筆空白＝非壓力計；`vibration_level` 有 41,000 筆空白＝溫度感測器。**那是設備本來就沒有這個量測，不要刪、不要補。**

### 全組共用的報告規則

1. 說「**紀錄筆數**」，不說「次數」。（連續幾筆可能是同一次事件）
2. 說「**關聯**」，不說「造成」「導致」。
3. 圖表標題寫成**結論句**，不只寫圖名。
4. 自訂的門檻，要說「是我們的分析門檻，不是設備規格」。
5. 工作表命名：`工作表_負責人_主題`，例如 `工作表_Mars_狀態比例`。
6. 檔名加日期，例如 `Mars_異常_1111.twbx`；最後一律存成**擷取版**。

## 1. 共同準備（三條線都要做）

### 1-1　連線與擷取

1. 開啟 Tableau → 左側「連線」→ **MySQL**。
2. 伺服器、連接埠、使用者、密碼：**向老師或組長索取**（密碼不要寫進任何檔案或貼到群組）。
3. 資料庫選老師指定的那個，把 **`iot_sensor_logs`** 從左側拖到畫布中央。
4. 右上角「連線」選「**擷取**」（不要選「即時連線」）。
5. 點下方「**工作表 1**」進入工作表；Tableau 會問你儲存擷取檔的位置，選你自己的資料夾即可。

**為什麼要擷取：** 即時連線的檔案裡沒有資料，換到沒裝資料庫驅動或連不上資料庫的電腦（例如上台用的電腦），圖表會是空的。

### 1-2　新增計算欄位「是否異常」（異常線必做；能耗線可略）

> **先想一下：「異常」要怎麼定義？** 只算 error？還是 warning、error、offline 都算？
> **這是全組要先決定的事**，不然三個人簡報上的「異常」數字會對不上。建議用「廣義異常」（不是 normal 就算），並在簡報上註明。

操作：
1. 上方選單「分析」→「**建立計算欄位…**」。
2. 名稱輸入：`是否異常`
3. 公式貼上：

```
IF [status] <> 'normal' THEN 1 ELSE 0 END
```

4. 按「確定」。它會出現在左側「度量」區。

> 若全組決定只算 error，改成：`IF [status] = 'error' THEN 1 ELSE 0 END`

### 1-3　找到「記錄數」

左側「度量」區最下方的 **`iot_sensor_logs (計數)`**（或「記錄數」）就是筆數，下面會用到。

## 2. 異常線（Mars）

### 圖 A1　狀態比例

**先想一下：** 主管想一眼看出「整體健康度」，長條圖和圓餅圖哪個容易看？
**建議：** 長條圖。圓餅圖在 94.7% 對 1.4% 這種懸殊的比例時，小區塊幾乎看不到。

**操作步驟（橫條圖）：**
1. 新增工作表，命名 `工作表_Mars_狀態比例`。
2. 左側「維度」的 **`status`** → 拖到「**列**」。
3. 左側「度量」的 **`iot_sensor_logs (計數)`** → 拖到「**欄**」。
4. 再把 **`status`** 拖到「**色彩**」，換成你喜歡的配色（normal 用灰藍，其他用橘、紅，讓異常顯眼）。
5. 把 **`iot_sensor_logs (計數)`** 再拖到「**標籤**」。
6. 在「標記」區的標籤欄位 `SUM(...)` 上：**右鍵 →「快速表計算」→「合計百分比」**。
7. 工具列按「**依值遞減排序**」的小圖示。
8. 圖表標題：雙擊標題，輸入結論句。

**你應該看到：**

| status | 筆數 | 百分比 |
|---|---:|---:|
| normal | 87,354 | 94.7% |
| offline | 1,801 | 2.0% |
| warning | 1,764 | 1.9% |
| error | 1,331 | 1.4% |

**怎麼解讀：**
- 整體非常健康，九成五紀錄正常。
- 異常合計約 5.3%（offline＋warning＋error）。
- 三種異常的比例差不多（1.4%–2.0%），沒有某一種特別突出。

**標題參考：** 「近九成五的紀錄為正常，異常約占五個百分點」

**怎麼講（三句）：** 「這張圖看整體狀態比例。94.7% 的紀錄是 normal，異常合計約 5.3%，其中 offline 最多、error 最少。對維運主管來說，整體設備是穩定的，要把力氣放在那少數的異常上。」

**常見錯誤：** 百分比加起來不是 100%——檢查「快速表計算」的計算依據是不是「表(向下)」（沿著 status 計算）。

### 圖 A2　機器種類 × 異常比例

**先想一下：** 溫度感測器有 20 台、壓力計 15 台、馬達 10 台。只比「異常筆數」公平嗎？
**答案：** 不公平，台數多的筆數自然多。要比「比例」。

**操作步驟（先做「比例」）：**
1. 新增工作表 `工作表_Mars_機器種類異常比例`。
2. **`device_type`** → 拖到「**列**」。
3. **`是否異常`** → 拖到「**欄**」，它會變成 `SUM(是否異常)`。
4. 在欄上的 `SUM(是否異常)`：**右鍵 →「度量」→「平均值」**（變成 `AVG(是否異常)`，也就是異常比例）。
5. 在 `AVG(是否異常)` 上：**右鍵 →「格式設定」→ 數字 →「百分比」→ 小數位數 2**。
6. 把 `AVG(是否異常)` 再拖到「**標籤**」。
7. 把 `device_type` 拖到「**色彩**」。
8. 排序：遞減。

**再做一張「筆數」對照（同一個活頁簿另開工作表）：** 重複上面，但第 4 步保留 `SUM(是否異常)`（不改平均值）。

**你應該看到：**

| 設備種類 | 異常筆數（廣義） | 異常比例（廣義） | 只算 error 的比例 |
|---|---:|---:|---:|
| motor | 945 | 4.61% | 1.88% |
| pressure_gauge | 1,691 | 5.50% | 1.32% |
| temperature_sensor | 2,260 | 5.51% | 1.31% |

**怎麼解讀：**
- **看筆數：** 溫度感測器最多（2,260），馬達最少（945）。但這是因為溫度感測器台數最多。
- **看比例：** 三種設備差不多（4.6%–5.5%），沒有哪一類明顯比較差。
- **只看 error：** 馬達最高（1.88%），約是其他兩類的 1.4 倍。
- **所以「異常」怎麼定義，會改變結論。** 這一點務必在簡報註明。

**標題參考：** 「三類設備的異常比例差異不大（4.6%–5.5%）；若只看 error，馬達最高」

**怎麼講：** 「這張圖比較三類設備的異常比例。用比例而不是筆數，因為三類設備的台數不同。馬達 4.61%、壓力計 5.50%、溫度感測器 5.51%，差距不大。若只看 error，馬達最高（1.88%）。這代表異常不是某一類設備特有的問題，但馬達的 error 值得多留意。」

**常見錯誤：** 欄位顯示「0」或很小——確認第 4 步有改成「平均值」，並把 `是否異常` 當成度量，不是維度。

### 圖 A3　異常機器排行

**先想一下：** 45 台設備，每台都是 2,050 筆。筆數排名和比例排名會不會不一樣？
**答案：** 一樣，因為每台筆數相同；所以只要畫筆數排行就可以。

**操作步驟：**
1. 新增工作表 `工作表_Mars_異常機器排行`。
2. **`device_id`** → 拖到「**列**」。
3. **`是否異常`** → 拖到「**欄**」（維持 `SUM`，也就是異常筆數）。
4. 排序：工具列「遞減」。
5. **只顯示前 10 名：** 把 **`device_id`** 拖到「**篩選器**」→ 切到「**頂端**」頁籤 →「依欄位」→ 選「頂端」「10」→ 依 `SUM(是否異常)` → 確定。
6. 把 `SUM(是否異常)` 拖到「**標籤**」，顯示數字。
7. `device_type` 拖到「**色彩**」，看前 10 名是哪類設備。

**你應該看到：** 前幾名是 TEM020 與 PRE012（各 132 筆）、TEM002 與 PRE011（各 130 筆）。**45 台的異常筆數介於 82–132，平均約 109。**

**怎麼解讀：**
- 第 1 名 132 筆，平均 109 筆，**只高約 21%**，差距不大。
- 所以不能說「某台設備特別有問題」，只能說「這幾台相對最多」。
- 前 10 名有 7 台溫度感測器、3 台壓力計，沒有馬達；馬達的異常比例較低，加上台數多的設備本來筆數就容易高。

**標題參考：** 「異常分散在各台設備，最多的 TEM020、PRE012 各 132 筆，與平均 109 筆差距不大」

**怎麼講：** 「這張圖把 45 台設備依異常筆數排名，只顯示前 10 名。最多的是 TEM020 和 PRE012，各 132 筆，但 45 台的平均是 109 筆，差距不大。這代表異常是分散的，沒有哪一台特別嚴重，維運不用只盯某一台。」

**說明平均值怎麼來的：** 全部異常筆數 4,896 ÷ 45 台 ≈ 109。簡報上寫出來即可，不必在圖裡畫線。

**加分題：** `factory_zone`（廠區）十個區域的異常比例有差嗎？比例大約在 4.1%–5.9%。**但每台設備出現在 3–4 個廠區，設備與廠區不是一對一，所以不要對廠區下結論。**

## 3. 能耗線（Tim）

### 圖 B1　各機器種類耗電比較

**先想一下：** 要比「總耗電」還是「平均每筆耗電」？兩個答案各代表什麼？
**答案：** 總耗電看「誰用掉最多電」，平均看「單台設備平均用多少」。兩個都要。

**操作步驟：**
1. 新增工作表 `工作表_Tim_機器種類耗電`。
2. **`device_type`** → 拖到「**列**」。
3. **`power_consumption`** → 拖到「**欄**」，預設是 `SUM`（總耗電）。
4. **`device_type`** → 拖到「**色彩**」。
5. **`power_consumption`** 再拖到「**標籤**」，在標籤欄位上：**右鍵 →「快速表計算」→「合計百分比」**，看占比。
6. 另開一張工作表，欄位的 `SUM` 改成「**平均值**」（欄位上右鍵 →「度量」→「平均值」），看平均每筆。

**你應該看到：**

| 設備種類 | 總耗電 | 占比 | 平均每筆 |
|---|---:|---:|---:|
| motor | 563,680 | **95.3%** | 27.5 |
| pressure_gauge | 15,313 | 2.6% | 0.50 |
| temperature_sensor | 12,299 | 2.1% | 0.30 |

**怎麼解讀：**
- 馬達只有 10 台（占設備 22%），卻用掉 95.3% 的電。
- 單筆平均，馬達是壓力計的 55 倍、溫度感測器的 92 倍。
- 結論：**節能的第一目標一定是馬達**。

**單位提醒：** 資料沒有提供耗電單位，**簡報只寫「耗電值」，不要寫 kWh**；單位向老師確認。

**標題參考：** 「馬達占整體耗電 95.3%，是節能最優先的設備」

**怎麼講：** 「這張圖比較三類設備的耗電。馬達總耗電占 95.3%，平均每筆是 27.5，壓力計和溫度感測器都不到 1。代表耗電幾乎全集中在馬達，要節能，應該從馬達著手。」

### 圖 B2　耗電排行

**先想一下：** 45 台一起排，前 10 名會是誰？這張圖還有資訊嗎？
**答案：** 前 10 名全是馬達。所以這張圖要告訴主管的是「馬達之間的差距有多大」。

**操作步驟：**
1. 新增工作表 `工作表_Tim_耗電排行`。
2. **`device_id`** → 拖到「**列**」。
3. **`power_consumption`** → 拖到「**欄**」（`SUM`）。
4. 排序：遞減。
5. **`device_type`** → 拖到「**色彩**」。
6. 篩選前 10 名：**`device_id`** → 拖到「**篩選器**」→「頂端」頁籤 → 頂端 10 → 依 `SUM(power_consumption)`。
7. `SUM(power_consumption)` 拖到「**標籤**」。

**你應該看到：** MOT007 56,929、MOT004 56,919、MOT009 56,679、MOT010 56,600、MOT002 56,374……前 10 名都是馬達，數值幾乎一樣。

**怎麼解讀：**
- 馬達之間**差距很小**（約 5.6–5.7 萬）。
- 前 3 名只占全部耗電約 28.8%，沒有某一台特別耗電。
- 結論：節能要針對整個馬達群，不是只改某一台。

**標題參考：** 「耗電前 10 名全是馬達，且彼此差距很小」

**怎麼講：** 「這張圖把 45 台設備依耗電排名，前 10 名全是馬達，數值都在 5.6 萬到 5.7 萬之間，差距很小。代表耗電是整個馬達群共同的，節能應該從整體馬達的運轉方式著手。」

### 圖 B3　時段趨勢

**先想一下：** 「時段」是看一天的哪個小時，還是看每天？你想回答主管什麼問題？
**答案：** 這裡看「一天內的哪個小時比較耗電」，目的是找出可以調整的時段。

**操作步驟：**
1. 新增工作表 `工作表_Tim_時段耗電`。
2. **`timestamp`** → 拖到「**欄**」，然後在欄位上**右鍵 → 選「小時」**（要選**離散**的「小時」，是日期部分，不是連續的時間）。
   - 若 `timestamp` 在左側顯示的圖示是「Abc」（文字），先到欄位上右鍵 →「變更資料類型」→「日期和時間」。
3. **`power_consumption`** → 拖到「**列**」，改成「**平均值**」。
4. 把 **`device_type`** 拖到「**篩選器**」→ 只勾選 **motor**（原因：馬達耗電約是其他設備的 55 倍，混在一起看不出任何差異）。
5. **Y 軸從 0 開始：** 在左邊 Y 軸上**右鍵 →「編輯軸」→ 勾選「包含零」**。
6. 標記類型選「**線**」。

**你應該看到：** 折線幾乎是水平的，馬達每小時平均耗電在 26.3（12 點）到 28.3（6 點）之間。

**怎麼解讀：**
- 最高與最低只差約 2（約 7%），**沒有明顯高峰或離峰**。
- **「沒有明顯時段差異」本身就是結論：** 耗電不隨時段變化，所以不需要鎖定特定時段做節能。
- 為什麼 Y 軸要包含 0？如果軸不從 0 開始，只放大 26–28 這一小段，看起來會像劇烈起伏，會誤導主管。

**標題參考：** 「馬達每小時平均耗電幾乎持平，沒有明顯的高峰或離峰」

**怎麼講：** 「這張圖看馬達一天內每小時的平均耗電。最高 28.3、最低 26.3，只差約 7%，沒有明顯的高峰離峰。代表耗電不隨時段改變，節能策略要放在設備本身，而不是調整運轉時段。」

**加分題（和「每日趨勢」的陷阱）：** 如果改畫「每天總耗電」，1/29 會特別低（約 1 萬，其他天約 1.9–2.4 萬），**因為 1/29 資料只到 11:57，不是真的用電少**。畫每日趨勢時要排除 1/29，或在圖上註明。

## 4. 感測值線（Kelly）

三張圖：馬達溫度分布、過熱排行、壓力與震動。這一線要用到兩個門檻（溫度 80°C、震動 15），**都是我們看資料分布自訂的分析門檻，不是設備規格**，簡報上要明講。

### 4-0　先建立兩個計算欄位

**① `溫度分類`（用來上色）**：分析 →「建立計算欄位…」，名稱 `溫度分類`，公式：

```
IF [temperature] > 80 THEN '過熱 (>80°C)' ELSE '正常 (≤80°C)' END
```

**② `是否過熱`（用來計數）**：名稱 `是否過熱`，公式：

```
IF [temperature] > 80 THEN 1 ELSE 0 END
```

**③ `震動分組`（圖 K3 用）**：名稱 `震動分組`，公式：

```
IF [vibration_level] >= 15 THEN '高(≥15)'
ELSEIF [vibration_level] >= 2 THEN '中(2–15)'
ELSE '低(<2)' END
```

> 為什麼是 80、2、15？80 是看直方圖：30–80°C 每一格都約 2,000 筆，超過 80 後突然掉到約 100 筆。15 是看壓力計資料：震動 14–15 之間有 95 筆、**零筆 error**；error 全部出現在 15 以上。2 大約是九成紀錄的上緣（九成紀錄在 1.86 以下）。

### 圖 K1　馬達溫度分布

**先想一下：** 想知道馬達「平常多熱、哪些算過熱」，要用折線、長條還是直方圖？
**答案：** 直方圖。直方圖把連續的溫度切成一格一格，看每一格有幾筆，最能看出分布。

**操作步驟：**
1. 新增工作表 `工作表_Kelly_馬達溫度分布`。
2. **`device_type`** → 拖到「**篩選器**」→ 只勾 **motor**（其他設備的溫度是 20 幾度，混進來會把分布弄亂）。
3. 在左側「度量」的 **`temperature`** 上：**右鍵 →「建立」→「組距…」**，大小輸入 `5`，名稱 `temperature (組距)`，確定。
4. 把 **`temperature (組距)`** 拖到「**欄**」（它會是藍色的離散，格子由左到右）。
5. 把 **`iot_sensor_logs (計數)`** 拖到「**列**」。
6. 把 **`溫度分類`** 拖到「**色彩**」，把「過熱」設成橘色、正常設成灰藍。
7. 把 `iot_sensor_logs (計數)` 拖到「**標籤**」顯示每格筆數。
8. 兩個軸的標題改中文：右鍵軸標題 →「編輯軸」→ 標題輸入「溫度（°C，每 5 度一格）」與「紀錄筆數」。

**你應該看到：**

| 項目 | 數字 |
|---|---|
| 馬達紀錄 | 20,500 筆 |
| 溫度範圍 | 30–109.06°C，平均約 55.9 |
| 超過 80°C | **408 筆（約 2%）** |
| 超過 100°C | 55 筆 |
| 80–95°C | 307 筆 |

**怎麼解讀：**
- 30–80°C 每一格大致平均（約 2,000 筆），代表馬達平常的溫度很分散、很穩定。
- 超過 80°C 後突然掉到約 100 筆一格，這是我們選 80 當門檻的原因。
- 過熱只占約 2%，是少數，但最高到 109°C，不能忽略。

**標題參考：** 「馬達溫度大多在 30–80°C，超過 80°C 的過熱紀錄約占 2%」

**怎麼講：** 「這張圖看馬達的溫度分布，用兩萬零五百筆馬達紀錄，每五度分一格，橘色是超過八十度的過熱紀錄。三十到八十度每格大約兩千筆，超過八十度的有四百零八筆，約占百分之二，最高一百零九度。代表馬達平常溫度穩定，過熱是少數但值得持續監控。八十度是我們依分布設的分析門檻，不是設備規格。」

**常見錯誤：** 直方圖變成一條線——組距要建立成「組距」而不是直接把 `temperature` 拖進欄；或 `device_type` 沒篩馬達，看到一堆 20 幾度的資料。

### 圖 K2　過熱排行

**先想一下：** 408 筆過熱，是集中在某一台，還是分散在 10 台？
**答案：** 要畫出來才知道，看排行圖。

**操作步驟：**
1. 新增工作表 `工作表_Kelly_過熱排行`。
2. **`device_type`** → 篩選器 → 只勾 **motor**。
3. **`device_id`** → 拖到「**列**」。
4. **`是否過熱`** → 拖到「**欄**」（維持 `SUM`，也就是過熱筆數）。
5. 工具列按「**遞減排序**」。
6. `SUM(是否過熱)` → 拖到「**標籤**」。
7. 軸標題改成「過熱紀錄筆數（>80°C）」。

**你應該看到：**

| 馬達 | MOT004 | MOT003 | MOT006 | MOT009 | MOT010 | MOT002 | MOT007 | MOT008 | MOT005 | MOT001 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 過熱筆數 | 48 | 45 | 44 | 43 | 41 | 40 | 39 | 39 | 38 | 31 |

**怎麼解讀：**
- **10 台馬達全部都有過熱紀錄**，從 31 到 48 筆，差距不大。

### 圖 K3　壓力與震動

**先想一下：** 想知道「壓力、震動」跟 error 有沒有關係，一個點代表一筆紀錄，你要用哪一種圖？
**答案：** 散佈圖。橫軸壓力、縱軸震動、用顏色標示 error。

**操作步驟（散佈圖）：**
1. 新增工作表 `工作表_Kelly_壓力與震動`。
2. **`device_type`** → 篩選器 → 只勾 **pressure_gauge**（只有壓力計有壓力值，溫度感測器沒有震動值）。
3. **`pressure`** → 拖到「**欄**」。
4. **`vibration_level`** → 拖到「**列**」。
5. 此時每個軸都是 `SUM(...)`，畫面只有幾個點。選單「分析」→ **取消勾選「聚合量值」**，這樣每一筆紀錄都會變成一個點。
6. **`status`** → 拖到「**色彩**」，把 **error 設成紅色**，其餘用淺灰或淡藍。
7. 軸標題改成「壓力」「震動程度」。

**操作步驟（檢查表）：** 另開工作表 `工作表_Kelly_震動分組檢查`。
1. `device_type` → 篩選器 → 只勾 **pressure_gauge**。
2. **`震動分組`** → 拖到「**列**」；**`status`** → 拖到「**列**」（放在震動分組右邊）。
3. **`iot_sensor_logs (計數)`** → 拖到「**文字**」（或「標籤」），標記類型選「**文字**」。
4. 分組順序：在左側 `震動分組` 上**右鍵 →「預設屬性」→「排序」→「手動」**，排成低、中、高。

**你應該看到：**

| 震動分組 | 筆數 | error | error 比例 |
|---|---:|---:|---:|
| 低(<2) | 29,752 | 270 | 0.91% |
| 中(2–15) | 868 | 9 | 1.04% |
| **高(≥15)** | **130** | **128** | **98.5%** |
| 合計 | 30,750 | 407 | |

高震動的 130 筆裡，128 筆 error、2 筆 offline，**沒有任何 normal 或 warning**。

**怎麼解讀：**
- 壓力高低跟 error 沒有明顯關係，紅點散在各種壓力。
- 震動超過 15 的區域，點幾乎全是紅色，error 比例從約 1% 跳到 98.5%。
- **但全部 407 筆 error 裡，約 69% 發生在低震動**，所以震動不是唯一原因。
- **分界太乾淨（130 筆沒有 normal），很可能 status 本來就是依震動門檻判定。** 這要問老師，不要說成「我們發現的規律」。

**標題參考：** 「壓力計震動 ≥15 時，130 筆中 128 筆為 error（98.5%）；其他範圍僅約 1%」

**怎麼講：** 「第三張看壓力計，橫軸壓力、縱軸震動，紅色是 error。壓力高低跟 error 沒有明顯關係，但震動超過十五的區域，點幾乎全是紅色。我另外做了檢查表：高震動共一百三十筆，其中一百二十八筆是 error，比例百分之九十八點五；低、中震動只有約百分之一。所以震動超過十五，值得優先檢查。不過全部 error 約七成落在低震動，震動不是唯一原因。」

**常見錯誤：** 散佈圖只有幾個點——第 5 步沒有取消「聚合量值」。

## 5. 分析與簡報

### 5-1　每張圖「講三句」公式

> ① 這張圖在比什麼　② 看到什麼（一個具體數字）　③ 對維運主管代表什麼

**自我檢查清單：**
- [ ] 數字是我自己從圖上讀出來的
- [ ] 說「紀錄筆數」，不說「次數」
- [ ] 沒用「造成」「導致」
- [ ] 自訂門檻有說「是分析門檻」
- [ ] 最後一句有說「主管該怎麼做」

### 5-2　怎麼分析一張圖（5 步，之後每張圖都能套用）

1. **問對象在乎什麼：** 維運主管在乎「會不會停機、先修哪裡、成本」。
2. **找基準：** 平均多少？門檻是多少？沒有規格就自訂並明講。
3. **比較：** 跟誰比？（設備類型、每台設備、時間）
4. **分清「筆數」與「比例」：** 設備數量不同時，用比例。
5. **最後一句：** 「所以主管應該……」。

### 5-3　常見錯誤對照

| 錯誤講法 | 為什麼不行 | 較安全的講法 |
|---|---|---|
| 「異常 4,896 次」 | 筆數 ≠ 次數 | 「4,896 筆紀錄是異常」 |
| 「溫度感測器最容易壞」 | 它台數最多，筆數自然多 | 「三類的異常比例差不多」 |
| 「TEM020 有問題」 | 132 筆對平均 109，差距不大 | 「異常分散，TEM020 最多但差距不大」 |
| 「某個時段耗電比較高」 | 圖上幾乎持平 | 「沒有明顯的時段差異」 |
| 「馬達耗電 xx kWh」 | 沒提供單位 | 「耗電值」 |
| 「馬達過熱了 408 次」 | 筆數 ≠ 次數 | 「有 408 筆紀錄超過 80°C」 |
| 「80°C 是危險溫度」 | 80°C 是我們自訂的 | 「我們以 80°C 作為分析門檻」 |
| 「高震動造成 error」 | 只看到同時出現，沒證明原因；且 130 筆沒有 normal，可能 status 本來就依震動判定 | 「震動 ≥15 時，error 比例明顯較高」 |
| 「震動是 error 的原因」 | 407 筆 error 中約 69% 在低震動 | 「震動 ≥15 是強訊號，但不是全部」 |

### 5-4　預備答辯

| 問題 | 建議回答 |
|---|---|
| 你們怎麼定義「異常」？ | 狀態不是 normal 就算，包含 warning、error、offline；這是我們的分析定義。若只算 error，馬達最高（1.88%）。 |
| 為什麼用比例，不用筆數？ | 三類設備台數不同（10、15、20），筆數會被台數影響。 |
| 排第一的那台，真的有問題嗎？ | 132 筆對平均 109 筆，差距不大，不能下這個結論。 |
| 耗電看不出時段差異，圖畫錯了嗎？ | 沒有畫錯，數字本身持平（26.3–28.3），「沒有差異」也是發現。 |
| 為什麼說「筆數」不說「次數」？ | 連續幾筆可能是同一次事件，筆數不等於事件數。 |
| 為什麼用 80°C 當過熱？ | 看直方圖：30–80°C 每格約 2,000 筆，超過 80 後掉到約 100 筆，所以以 80 為分界。這是分析門檻，不是設備規格；有規格就換成規格值。 |
| 震動的 2、15 怎麼來的？ | 14–15 之間 95 筆、零筆 error；15 以上 130 筆中 128 筆 error。2 約是九成紀錄的上緣。都是分析用，不是規格。 |
| 高震動是 error 的原因嗎？ | 不能這樣說，只能說高震動時 error 比例很高；130 筆裡沒有 normal，可能 status 本來就依震動判定，想向資料方確認。 |
| 資料只有 29 天，結論能推到全年嗎？ | 不能，只代表這 29 天，看不到季節或長期趨勢。 |
| 這份資料看得出原因嗎？ | 描述性分析只說「看到什麼」，沒有維修紀錄，無法說「為什麼」。 |

### 5-5　要一起問老師的三件事

1. `status` 是依什麼規則判定的？是否依感測值門檻？
2. `power_consumption`、`vibration_level` 的單位是什麼？
3. 設備是否有規格上的溫度、震動警戒值？
